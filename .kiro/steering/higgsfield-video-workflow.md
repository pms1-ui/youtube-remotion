# Higgsfield 영상 제작 워크플로우

사용자가 "스크립트 줄게, 힉스필드(Higgsfield)로 영상 만들어줘" 류의 요청을 하면
아래 절차를 순서대로 자동 진행한다. 이 문서는 260905 구르카 편 작업에서 검증된 절차다.

## 0. 기본값 (사용자가 다르게 지정하지 않으면 이대로)
- 이미지 모델: `gpt_image_2` (레퍼런스 이미지용, quality high, resolution 2k)
- 영상 모델: `seedance_2_5`
- 영상 길이: 5초 (duration: 5)
- 화질: 1080p (resolution)
- 비율: 4:3 (aspect_ratio) — 사용자가 세로/가로 지정하면 그에 맞춤
- 톤(기본): 밀리터리/남자다운/선명한 시네마틱. 사용자가 톤 주면 그걸 우선.
- 유혈/폭력: 항상 순화. "no blood, no graphic violence, no contact" 류를 프롬프트에 명시.

## 1. 스크립트 → 장면 분할
- 사용자가 준 스크립트를 문장(또는 의미 단위)별로 끊어 장면 리스트를 만든다.
- 각 장면에 1부터 번호를 매긴다. 연속성을 위해 장면 간 흐름(시간·공간·인물)이 이어지도록 프롬프트를 설계한다.

## 2. 레퍼런스 이미지 생성 (일관성의 핵심)
- 먼저 주인공/핵심 피사체 레퍼런스 이미지 1장을 `gpt_image_2`로 만든다.
- 중요: 레퍼런스는 **얼굴 정면 클로즈업으로 너무 강하게 만들지 말 것.**
  인물이 화면 중앙에 크게 박히면 영상마다 그대로 복사돼 어색하고 연속성이 깨진다.
  → 인물을 상황/배경 속에 자연스럽게 녹인 구도(승객 속, 환경 와이드 등)로 만든다.
- `job_status`를 sync:true로 폴링해 완료되면 결과 URL/job_id 확보.

## 3. 영상 배치 생성
- 장면이 여러 개면 `generate_video_batch`로 병렬 제출한다. (각 item에 stable index 부여)
- 각 영상 params:
  - `mode: "omni_reference"`, `medias: [{value: <레퍼런스 job_id>, role: "image_references"}]`
  - `duration: 5`, `resolution: "1080p"`, `aspect_ratio: "4:3"`
- 레퍼런스는 `image_references` 역할로만 넣는다.
  - **start_image / end_image 로 넣지 말 것** (레퍼런스가 시작/끝 프레임이 되면 안 됨).
- 레퍼런스에 과의존하지 않도록, 프롬프트 안에서 인물 외형을 직접 다시 묘사한다.
  (레퍼런스는 톤/인물 힌트로만 쓰고, 구도는 프롬프트가 주도)
- 소품(예: 칼)은 장면상 필요할 때만. 필수로 넣지 않는다.

## 4. 흔한 제출 실패 대응
- **프리셋 추천으로 막힘** ("Preset ... was recommended instead of submitting"):
  → 해당 index를 `declined_preset_id: <반환된 preset id>` 붙여 재제출.
- **NSFW 필터 실패** (status: nsfw):
  → 위협/폭력 묘사를 더 순화(접촉·유혈 제거, "긴장된 대치" 수준)해 재생성.
- **Out of credits 일시 오류**: `balance`로 실제 잔액 확인. 남아있으면 재시도.

## 5. 완료 대기
- `jobs_wait`로 최대 12개씩 그룹 폴링. all_terminal 될 때까지 반복.
- 전부 terminal 되면 `show_generation_by_ids`로 한 번에 정렬 표시.

## 6. 로컬 다운로드 (항상 마지막에 수행)
- 저장 경로: `youtube-remotion/video_output/<주제>_<YYMMDD>/`
- 파일명: 장면 순서 번호 + 짧은 영문 설명 (예: `01_train_robbers.mp4`).
  - 중간 삽입 컷은 `01b_`, `01c_` 식으로 사이 번호를 준다.
  - 재생성분은 기존 파일명을 덮어쓴다.
  - 레퍼런스 이미지도 `00_reference.png`(재생성 시 `_v2`)로 함께 저장.
- 다운로드는 PowerShell `Invoke-WebRequest` 사용.
  - **반드시 `$ProgressPreference='SilentlyContinue'`를 먼저 설정** (안 하면 진행바가 로그를 수만 줄 오염시킴).
  - 여러 파일은 한 줄 명령에서 `;`로 이어 순차 다운로드.
- 다운로드 후 `Get-ChildItem`으로 파일 크기 확인해 깨짐/누락 없는지 검증.

## 7. Higgsfield 히스토리/생성물 정리 (다운로드·검증 완료 후에만)
- 목적: 로컬로 안전하게 내려받은 뒤에는 Higgsfield 클라우드 히스토리와 생성 파일을 전부 삭제한다.
- **전제 조건 (반드시 먼저 통과):** 6번의 로컬 파일 크기 검증이 끝나 깨짐/누락이 없어야 한다.
  삭제는 되돌릴 수 없고, 삭제하면 로컬 파일이 유일본이 되므로 검증 전에는 절대 삭제 단계로 넘어가지 않는다.
- **중요 제약 — MCP로는 개별 삭제 불가:**
  - Higgsfield MCP 도구에도 공식 기능에도 완료된 개별 이미지/영상을 삭제하는 기능이 없다.
  - 존재하는 삭제 수단은 (a) 계정 전체 삭제(모든 생성물·캐릭터·프로젝트 제거, 과함),
    (b) 생성 중 취소(완료본은 대상 아님)뿐이다.
  - 따라서 완료된 생성물의 개별 삭제는 **웹 대시보드(Assets)에서 사용자가 수동으로** 해야 한다.
- **에이전트가 할 일:**
  1. 이번 작업에서 만든 전체 생성물(이미지·영상)의 job_id / 파일명 / URL 목록을 표로 정리해 제시한다.
     (`show_generations`로 image·video 각각 조회해 이번 세션 생성분을 식별)
  2. 사용자에게 "로컬 저장·검증 완료됐고, 이제 Higgsfield Assets에서 아래 항목들을 삭제하면 된다"고 안내한다.
  3. 삭제 경로 안내: higgsfield.ai 로그인 → Assets(생성물 목록)에서 해당 타일 선택 → 삭제.
- MCP에 개별 삭제 도구가 새로 생기면 그때 자동화로 전환한다(주기적으로 도구 목록 확인).

## 8. 마무리 보고
- 장면별 파일명·상태(유지/신규/재생성)·내용을 표로 정리해 사용자에게 보고.
- 사용자에게 직접 영상 확인을 요청한다(생성은 했으나 화면이 의도대로인지는 사람이 확인).
- 7번 삭제 대상 목록을 함께 제시한다.
- 남은 크레딧을 필요 시 언급.

## 참고: 인증
- Higgsfield MCP는 원격 서버(mcp.higgsfield.ai/mcp), OAuth 로그인 방식.
- 유저 레벨 mcp.json에 `"higgsfield": { "url": "https://mcp.higgsfield.ai/mcp" }` 로 등록.
- 인증 확인은 `balance` 호출로. "session expired" 나오면 커넥터 제거→재추가로 로그인 트리거.
